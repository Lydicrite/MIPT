# Обработка изображений и аудио

Решение основано на `Examples/3_2_file_processing`: сохранены форматы
гистограмм, разделение чтения и обработки, статистическая коррекция.
Как и в примере, изображения обрабатываются в оттенках серого, 8 бит
на пиксель. Цветные изображения при чтении преобразуются в режим `L`.
Для цветных, 16-битных и многокадровых изображений это не сохранение
исходного формата: обрабатывается только первый кадр в 8-битном виде.

Алгоритмы подсчёта гистограммы и преобразований реализованы явно.
Pillow используется для чтения, записи и применения таблицы преобразования
пикселей. Устанавливать OpenCV, NumPy и SciPy не требуется.

## Структура

- `main.py`: разбор аргументов, вызовы операций, сохранение результатов.
- `file_io.py`: автоматический выбор чтения по расширению и запись данных.
- `histogram.py`: подсчёт 256 уровней, проверка и нормировка гистограмм.
- `image_processing.py`: эквализация, гамма- и статистическая коррекция.
- `audio_processing.py`: чтение и запись PCM WAV, квантование аудио.

## Запуск

Команды выполняются из корня `f:\Lydicrite\MIPT\Python`:

```powershell
python -m pip install -r "Lesson_3.py/2/requirements.txt"
python "Lesson_3.py/2/main.py" --help
```

Обязательные аргументы: `-p / --path` и `-m / --operation`.
Аргумента `--type` больше нет: функция чтения выбирается из словаря
`READERS` по `Path(path).suffix.lower()`, включая расширения в верхнем регистре.
Отдельный аргумент `--img_path` также не нужен.

Операции: `histogram`, `equalize`, `gamma`, `quantize`, `stat`.
`-o / --output` задаёт выходной файл. Если он опущен, результат записывается
в `Lesson_3.py/2/output/<имя>_<операция>.<расширение>`.
Папки для результатов создаются автоматически. Входные файлы защищены
от перезаписи; уже существующий отдельный выходной файл перезаписывается.
Относительные пути аргументов считаются от текущей рабочей папки.

```powershell
# Гистограмма изображения: 256 значений, количество пикселей
python "Lesson_3.py/2/main.py" -p "Examples/3_2_file_processing/input_data/cells.jpg" -m histogram

# Эквализация и гамма-коррекция
python "Lesson_3.py/2/main.py" -p "Examples/3_2_file_processing/input_data/sar_1_gray.jpg" -m equalize
python "Lesson_3.py/2/main.py" -p "Examples/3_2_file_processing/input_data/sar_1_gray.jpg" -m gamma --gamma 0.5

# Статистическая коррекция из исходного примера
python "Lesson_3.py/2/main.py" -p "Examples/3_2_file_processing/input_data/cells.jpg" -m stat --reference "Examples/3_2_file_processing/input_data/json_test.json"

# Пересохранение готовой гистограммы в другом формате
python "Lesson_3.py/2/main.py" -p "Examples/3_2_file_processing/input_data/txt_test.txt" -m histogram -o "Lesson_3.py/2/output/converted.json"
```

### Форматы

| Расширение                                         | Содержимое                                                                   |
| ------------------------------------------------------------ | -------------------------------------------------------------------------------------- |
| `.png`, `.jpg`, `.jpeg`, `.bmp`, `.tif`, `.tiff` | Изображение                                                                 |
| `.txt`                                                     | Пары`уровень значение`, разделённые пробелами |
| `.csv`                                                     | Две колонки`уровень,значение`, без заголовка    |
| `.json`                                                    | Объект`{"keys": [...], "values": [...]}`                                       |
| `.bin`                                                     | Ровно 256 чисел IEEE 754 float32, little-endian, 1024 байта             |
| `.wav`                                                     | Несжатое целочисленное PCM-аудио                             |

Табличные файлы содержат **уже готовую гистограмму**, а не последовательность
отсчётов. Операция `histogram` для них пересохраняет значения, при
`--normalize` делит их на сумму. Пропущенные уровни заполняются нулями,
повторяющиеся ключи, отрицательные и неконечные значения отклоняются.
BIN совместим с примером на Windows; float32 может округлять большие
счётчики и вероятности. Для точного хранения целых счётчиков предпочтителен JSON.

## 2.a. Эквализация гистограммы

Цель: повысить контраст, распределив встречающиеся яркости по более широкому
диапазону. Используется накопленная гистограмма, а не линейное растяжение.

1. Считаем `h[k]`: количество пикселей яркости `k`, где `k = 0..255`.
2. Находим накопленные количества `C[k] = h[0] + ... + h[k]`.
3. Определяем `C_min`: первое ненулевое значение `C`.
4. Строим таблицу преобразования и заменяем каждый пиксель.

```text
N = число пикселей
T[k] = round(255 * (C[k] - C_min) / (N - C_min))
output[x, y] = T[input[x, y]]
```

Значения таблицы ограничиваются диапазоном `0..255`. Вычитание `C_min`
позволяет отобразить минимальную встречающуюся яркость в 0.
Для однотонного изображения `N == C_min`: оно возвращается без изменений,
чтобы избежать деления на ноль. Округление выполняется функцией Python `round`;
побитовое совпадение с OpenCV на всех пограничных случаях не гарантируется.
Эквализация не обязана давать идеально равномерную дискретную гистограмму.

Принцип и демонстрация `equalizeHist`:
[OpenCV 4.13.0: Histogram Equalization](https://docs.opencv.org/4.13.0/d4/d1b/tutorial_histogram_equalization.html).

## 2.b. Гамма-коррекция

Используется формула из указанного руководства OpenCV:

```text
output = round(255 * (input / 255) ** gamma)
```

- `0 < gamma < 1`: осветление.
- `gamma == 1`: изображение не меняется.
- `gamma > 1`: затемнение.

Важно: показателем является именно `gamma`, а не `1 / gamma`.
Допускается только конечное положительное число. Таблица из 256 значений
строится один раз, затем применяется ко всем пикселям. В отличие от
эквализации, эта операция не использует распределение яркостей изображения.
Конечный результат остаётся 8-битным: часть близких уровней может объединиться.

Источник:
[OpenCV 3.4.20: Gamma correction](https://docs.opencv.org/3.4.20/d3/dc1/tutorial_basic_linear_transform.html).

### Статистическая коррекция

Операция `stat` сохранена из исходного примера:

```text
output = target_std * (input - source_mean) / source_std + target_mean
```

Эталон задаётся через `--reference`: изображение или файл гистограммы.
Перед вычислением среднего и стандартного отклонения гистограммы нормируются.
Результат округляется и ограничивается диапазоном `0..255`. Из-за этого
выходные статистики могут не совпасть с эталоном точно. Однотонный источник
отклоняется, поскольку `source_std == 0`. Это согласование среднего и
отклонения, а не полное выравнивание двух распределений.

## 4. WAV и квантование

### Выбор средств

WAV является контейнером RIFF, а не единственным способом кодирования звука.
Здесь выбран стандартный модуль Python `wave`, позволяющий читать параметры,
получать PCM-байты и записывать корректный заголовок через `writeframes`.
Он не требует сторонних библиотек, но не поддерживает сжатый и IEEE float WAV.
Для таких файлов сначала требуется преобразование в integer PCM; альтернативой
была бы библиотека с поддержкой соответствующего кодека.

Поддерживаются PCM 8, 16, 24 и 32 бит, моно и несколько каналов:

- 8-битные отсчёты WAV беззнаковые: `0..255`, тишина соответствует 128.
- 16/24/32-битные отсчёты знаковые, little-endian.
- Внутри `AudioData` все отсчёты представлены знаковыми целыми числами.
- Отсчёты идут по кадрам с чередованием каналов: `L0, R0, L1, R1, ...`.
- Проверяется наличие всех байтов, указанных в заголовке WAV.

### Гистограмма и квантование

Для разрядности `B` исходный знаковый диапазон:
`[-2**(B-1), 2**(B-1)-1]`. Делим его на 256 одинаковых интервалов:

```text
offset = 2 ** (B - 1)
step = 2 ** (B - 8)
q = (sample + offset) // step
h[q] += 1
```

В коде деление на степень двойки выполнено битовым сдвигом.
`q` лежит в `0..255` и одновременно является индексом бина
и байтом выходного 8-битного PCM. Тишина переходит в 128.
Крайние амплитуды переходят в 0 и 255. Для исходного 8-битного WAV
квантование сохраняет все отсчёты без изменений.

Это равномерное квантование с отбрасыванием младших битов, без дизеринга
и без нормировки громкости по пикам записи. Оно вносит ошибку квантования;
например, 16-битные значения группируются по 256 соседних уровней.
Все каналы учитываются в общей гистограмме:
сумма счётчиков равна `число кадров * число каналов`.
Порядок отсчётов для WAV сохраняется, гистограмма **не используется вместо
звукового сигнала** и сортировка отсчётов не производится.

При записи сохраняются частота дискретизации, число каналов и число кадров
(следовательно, длительность). Разрядность становится 8 бит. Комментарии,
дополнительные RIFF-метаданные и маска расположения каналов не переносятся.
Файл читается в память целиком; решение рассчитано на учебные записи.
Пустой WAV даёт нулевую гистограмму; её нормировка невозможна.

### Команды для WAV

В следующих командах `input.wav` нужно заменить путём к своей PCM-записи:

```powershell
# Только гистограмма из 256 бинов
python "Lesson_3.py/2/main.py" -p "input.wav" -m histogram -o "Lesson_3.py/2/output/audio_hist.json"

# Квантованный WAV и автоматически создаваемая audio_8bit.hist.json
python "Lesson_3.py/2/main.py" -p "input.wav" -m quantize -o "Lesson_3.py/2/output/audio_8bit.wav"

# Явный путь и нормировка гистограммы, WAV остаётся тем же
python "Lesson_3.py/2/main.py" -p "input.wav" -m quantize --histogram-output "Lesson_3.py/2/output/audio_hist.csv" --normalize
```

При `quantize` сохраняются и последовательность в WAV, и гистограмма исходных
отсчётов по тем же 256 интервалам. Она совпадает с гистограммой байтов
квантованного WAV. PNG рекомендуется для изображений, если важно сохранить
вычисленные уровни точно: JPEG является форматом с потерями.

### Документация WAV

  `open`, `getnchannels`, `getsampwidth`, `getframerate`, `readframes`,
  `setnchannels`, `setsampwidth`, `setframerate`, `writeframes`.
- [McGill: WAVE specifications](https://www.mmsp.ece.mcgill.ca/Documents/AudioFormats/WAVE/WAVE.html):
  структура RIFF, PCM, little-endian, знаковые и беззнаковые отсчёты.
- В Python 3.12+ модуль `wave` также читает `WAVE_FORMAT_EXTENSIBLE`,
  если подформат является PCM. Для решения рекомендуется Python 3.12+.
